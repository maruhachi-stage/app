# テスト方針

このドキュメントでは、`user`、`staff`、`api` にテストを追加するときの種類・配置・命名・優先順位を定義します。テストランナーは各アプリの `package.json` に定義された `test` スクリプトから実行します。

## テスト種別と責務

| 種別 | 対象 | 外部依存 | 目的 |
| --- | --- | --- | --- |
| Unit | 純粋関数、ドメインロジック、UIの小さな振る舞い | 原則モック | 条件分岐や境界値を高速に検証する |
| Integration | APIクライアント、ルート、サービス、リポジトリ間の連携 | 必要に応じてモック・テスト用アダプター | 複数モジュールの契約とデータ変換を検証する |
| E2E | ユーザーが行う一連の画面操作と主要APIフロー | 起動したアプリ、テスト用DB | 重要な業務フローが環境をまたいで動くことを検証する |

### アプリごとの主な対象

- `user`: 予約フローの状態遷移、フォーム、表示用の変換をUnitで検証し、主要な予約操作をE2Eで検証します。
- `staff`: スタッフ画面の入力・一覧操作、権限に応じた表示をUnit/Integrationで検証します。
- `api`: ドメイン・サービスをUnitで検証し、ルートからレスポンスまでの契約をIntegrationで検証します。

## 配置と命名

- Unit/Integrationテストは、対象コードに近い場所へ `__tests__` ディレクトリまたは `*.test.ts` / `*.test.tsx` として配置します。
- E2Eテストは対象アプリ直下の `e2e/` に配置します。
- テスト名は対象の振る舞いを表す英語の `*.test.ts` / `*.test.tsx` とし、テストケースの説明は日本語で具体的に書きます。
- 1つのテストファイルでは、同じ責務の対象だけを扱います。

## Mock・Fixture・テストデータ

- 外部API、時刻、乱数、メール送信、データベースなど、テストの再現性を損なう依存はMockまたはテスト用アダプターに置き換えます。
- 複数テストで再利用する固定データは、各アプリの `tests/fixtures/` にまとめます。
- テストケース内でしか使わないデータは、テストファイル内に最小限のファクトリーとして定義します。
- 実環境の認証情報・個人情報・本番データは使用しません。

## 優先順位

1. 予約・決済・認証など、失敗時の影響が大きいフロー
2. 境界値、入力エラー、権限エラーなどの失敗経路
3. APIの入出力契約とデータ変換
4. 補助的な表示や低リスクな分岐

新機能や不具合修正では、まずUnitまたはIntegrationテストで再現条件を固定し、必要な場合にE2Eテストを追加します。

## Workers ランタイム上の結合テスト

`api` は Cloudflare Workers（D1 / R2）で動作するため、ユニットテストも結合テストも Workers ランタイム上で実行します。ローカルとテストで実行環境が分かれないよう、設定は `vitest.config.ts` の1つだけです。

- 実行: `cd apps/api; npm test`（`src/**/*.test.ts` と `test/workers/**/*.test.ts` を同じ環境で実行）
- 結合テストだけを実行: `npm run test:integration`
- ランナー: `@cloudflare/vitest-plugin`。`wrangler.jsonc` のバインディングをそのまま読み込むため、本番と同じ D1 方言・R2 バインディングで検証できます。
- DB: 各テストは独立した D1 を持ち、`test/workers/setup.ts` が `d1/migrations` を適用して `d1/seed.sql` を投入します。スキーマは本番と同じ migration を唯一の正とします。
- リクエスト: `SELF.fetch` を使い、実際の Worker エントリポイント（`fetch` ハンドラ）へ HTTP 相当のリクエストを送ります。
- 対象: 公開 API の契約（ステータスコード・レスポンス形）、予約の座席競合、管理者ログインの失敗経路、`/images/*` の 404 など。
- D1 に固有の挙動（`batch` の原子性、一意制約）は実 DB で検証し、モックでは代替しません。

## 実行方法

各アプリのディレクトリで実行します。

```powershell
npm test
```

CIでは各アプリの `test` スクリプトを実行し、E2Eなど起動環境が必要なテストは専用ジョブへ分離します。
